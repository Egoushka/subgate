# v0.1 spec: see the week

- Status: proposed
- Milestone: "See the week" (roadmap.md)

## Goal

Every subscription call from the owner and their automation passes through subgate, which reads the plan's own weekly meter, attributes the use to each consumer, and shows it as gauges and JSON. It never acts on a request. After a week of real traffic the attribution is checked against the gateway's per-key token counts, and that check decides whether v0.2 can gate on it.

## In scope

- `proxy`: `httputil.ReverseProxy` to a configured upstream; streaming tap with a bounded channel; observe mode only.
- `provider/anthropic`: parse `anthropic-ratelimit-unified-*` into window snapshots; parse usage from `message_start`, `message_delta` and non-streamed JSON bodies, incrementally, with a per-request cap.
- `engine`: windows, pace line, states, both attribution estimators (ADR 0005), quiet-hours fit of k.
- `store/sqlite` (and `store/memory` for tests); `policy` from a YAML file.
- `GET /healthz`, `GET /v1/status`, `GET /metrics`.
- `subgate hash <value>`, `subgate env`, `subgate serve`.
- Container image, release-please, CI (ADR 0011), an example config with placeholder consumers.

## Out of scope

Any action (`hold`, `api`, `cheap`), the write API, approvals, the ledger, a second provider. No change to the gateway's caps or keys.

## Acceptance checks

Each runs on a machine and can fail. `go test` names are in the package shown.

### Tests (`go test ./... -race`)

| # | Check | Passes when |
|---|---|---|
| T1 | `engine.TestPaceLine` | allowance at 0, 3.5 and 7 days elapsed is 0, share/2 and share; unused allowance carries forward |
| T2 | `engine.TestStates` | OK, OVER_PACE (consumer and account backstop), LIMITED until reset, STALE after the configured age |
| T3 | `engine.TestAttributionSimulation` | worst consumer p95 error ≤ 5 points of the week in every cell of the ADR 0005 table, 40 seeds |
| T4 | `engine.TestWeekRollover` | a new `7d-reset` starts new counters; the old week is kept |
| T5 | `anthropic.TestParseLimitHeaders` | synthetic fixture with all eight headers → snapshot fields; missing headers → no snapshot, no error |
| T6 | `anthropic.TestStreamUsage` | a recorded-shape SSE stream split at every byte offset gives the same usage as `message_delta` |
| T7 | `proxy.TestForwardsUnchanged` | `authorization`, `user-agent`, `x-app`, `anthropic-beta` and the body reach the upstream byte-identical |
| T8 | `proxy.TestTapNeverBlocks` | with an engine that sleeps 1 s per event, TTFB through the proxy stays within 5 ms of direct; drops are counted |
| T9 | `proxy.TestTapPanicStillForwards` | a panicking tap: the client still gets the full 200 stream |
| T10 | `proxy.TestUpstream429` | a mock 429 with limit headers reaches the client unchanged; `/v1/status` shows LIMITED until the reset |
| T11 | `proxy.TestObserveNeverActs` | a consumer at 3× its share still gets 200 |
| T12 | `proxy.TestNoCredentialInLogs` | a sentinel token in `authorization` appears in no log line and no store row |
| T13 | `cmd.TestEnvFailsOpen` | `subgate env` prints the direct URL when `/healthz` is closed or slower than 500 ms, the subgate URL otherwise |
