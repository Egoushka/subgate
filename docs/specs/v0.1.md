# v0.1 spec: see the week

- Status: proposed (ledger-first rewrite, 2026-10-29)
- Milestone: "See the week" (roadmap.md)

## Goal

Every automated job on the owner's subscription asks subgate before it starts and reports what it used; a sampler and the owner's status line keep the plan's meter fresh. subgate attributes the week to each consumer and shows it as gauges and JSON. It never refuses a job: `admit` always answers `allow`, with `would` showing what enforce mode would answer, and `subgate run` runs the job even when subgate is down. After a week of real use, a holdout test checks the attribution against the meter itself, and that check decides whether v0.2 can enforce on it.

## In scope

- The engine, as `Switchknife.Pace` in the switchknife repository (ADR 0004): windows, pace line, states, leases, both attribution estimators (ADR 0005), the quiet-hours fit of k.
- The Anthropic provider: parse `rate_limit_event`, the `/usage` report, status-line `rate_limits` and a run's `modelUsage` into observations.
- SQLite store (and in-memory for tests); policy from a YAML file.
- API: `POST /v1/admit` (observe mode), `POST /v1/usage`, `POST /v1/signal`, `GET /v1/status`, `GET /metrics`, `GET /healthz`.
- CLI: `serve`, `run`, `sample`, `statusline`, `token new`.
- Container image, release-please, CI (ADR 0011), an example config with placeholder consumers.

## Out of scope

Enforcement and the `hold`, `api` and `cheap` decisions; the admin API (`/v1/consumers`, audit); approvals; any proxy; a second provider.

## Acceptance checks

Each runs on a machine and can fail. Test names are given as component and name (`engine` tests live in switchknife's `Switchknife.Pace.Tests`, the rest in this repository). `scripts/check.sh` in each repository runs its suite (`dotnet test`) and prints each check id with pass or fail.

### Tests

| # | Test | Passes when |
|---|---|---|
| T1 | engine `PaceLine` | allowance at 0, 3.5 and 7 days elapsed is 0, share/2 and share; unused allowance carries forward |
| T2 | engine `States` | OK, OVER_PACE (consumer, and the account backstop), LIMITED until reset, STALE after the configured age |
| T3 | engine `AttributionSimulation` | worst consumer p95 error ≤ 5 points of the week in every cell of the ADR 0005 table, 40 seeds |
| T4 | engine `WeekRollover` | a new weekly `resets_at` starts new counters; the old week is kept |
| T5 | engine `Leases` | an open lease counts toward `used`; usage closes it with actual use; expiry releases it and logs it as unreported |
| T6 | engine `ObserveNeverDenies` | a consumer at 3× its share gets `allow` with `would: hold` |
| T7 | anthropic `ParseRateLimitEvent` | Python shape with `rate_limit_type` → that window; TypeScript shape → 5-hour window when `resetsAt` is ≤ 5 h away, else 7-day (ADR 0012); unknown fields ignored |
| T8 | anthropic `ParseUsageReport` | `limits[]` rows `session`, `weekly_all` → 5-hour and 7-day windows (`percent` 0–100, ISO `resets_at`); `weekly_scoped` kept with its scope; `rate_limits: null` → no observation, no error |
| T9 | anthropic `ParseStatusLine` | status-line JSON with and without `rate_limits` → a signal (`used_percentage` ÷ 100) or none, plus an owner usage report from `session_id` and `cost.total_cost_usd`; the printed line still renders |
| T10 | anthropic `ParseRunResult` | `modelUsage` with several models → one usage report with per-model cost |
| T11 | cli `RunReportsUsage` | `subgate run -- <fake claude that prints recorded stream-json>`: admit, then signal and usage posted; the command's exit code is passed through |
| T12 | cli `RunWhenUnavailable` | observe mode, subgate down: `subgate run` starts the command, queues its report in a local file, and sends it once subgate is back; with `--on-unavailable=hold` it doesn't start the command and exits 75 |
| T13 | cli `StatuslineFailsOpen` | with subgate down or slower than 300 ms, `subgate statusline` prints its line within 400 ms and exits 0 |
| T14 | api `Auth` | `usage` and `admit` without a consumer token → 401; a signal token can post `signal` only (403 elsewhere); tokens appear in no log line and no store row |
| T15 | api `NoCredentialsAccepted` | a request body or header carrying an `sk-ant-` value is rejected with 400 and not stored |
| T16 | engine `CumulativeSessionUsage` | owner reports of one session's running total 0.10, 0.25, 0.25, 0.40 count 0.40 in all; a lower total is ignored |
| T17 | policy `Validate` | shares summing past 100%, an unknown action, or a duplicate token hash → start fails with the reason |
| T18 | store `SurvivesRestart` | counters, open leases and the last meter are the same after closing and reopening the SQLite file |
| T19 | engine `CalibrateQuietHoursOnly` | meter rises outside quiet hours don't change k; inside them they do |
